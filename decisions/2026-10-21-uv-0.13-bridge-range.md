# uv 0.13 bridge range

## Decision: move to uv 0.13, with `required-version` still admitting Dependabot's 0.12.18

- `mise.toml`: `uv = "0.13"`.
- `[build-system] requires`: `uv_build>=0.13.2,<0.14.0`.
- `tool.uv.required-version`: `>=0.12.18,<0.14`.

Raise the `required-version` floor to `>=0.13` once dependabot-core ships uv
0.13 (dependabot/dependabot-core#16639, 0.12.18 → 0.13.4, open on 2026-10-21).

## Context: why it came up

Dependabot opened #75, moving `uv_build` to `>=0.13.0,<0.14.0` while uv itself
stayed on the 0.12 series. The two move together, so on 2026-10-21 Robin chose
to move the template to the uv 0.13 series with a 0.13.2 floor.

uv refuses to run outside `tool.uv.required-version`. Dependabot runs its own
uv, `uv==0.12.18` in `dependabot-core/uv/helpers/requirements.txt`. A
`required-version` floor of 0.13.2 would fail every Python Dependabot PR, the
reason `2026-10-14-uv-lock-revision-flapping.md` rejected even `>=0.12.22`.

## Alternatives considered

- **`required-version = ">=0.13.2,<0.14"` now.** Rejected: every Python
  Dependabot PR fails until dependabot-core#16639 ships and is deployed.
- **Wait for Dependabot, then move.** Rejected: it leaves #75 open, and the
  template that other repositories copy stays on 0.12 for an unknown time.

## Reasoning

`setup-uv` installs the newest uv in `required-version`, so CI and the
sync-lockfile job run 0.13.x. mise provides 0.13.x locally. Only Dependabot
runs 0.12.18, and the range admits it. `uv_build` is fetched into an isolated
build environment, so a 0.13 backend does not need a 0.13 front end.

## Trade-offs accepted

- Until the floor is raised, `required-version` admits a 0.12 uv that nobody
  but Dependabot should be running.
- Lockfiles written by Dependabot's 0.12.18 and by CI's 0.13.x may carry
  different `revision` values; see `2026-10-14-uv-lock-revision-flapping.md`.
